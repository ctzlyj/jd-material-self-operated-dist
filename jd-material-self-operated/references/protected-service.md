# Protected service boundary

This distribution retains local CLI commands, caches and business adapters but does not contain the listed private core implementations. Each core request requires a real ERP identity and the server's current permission for this specific product. Plugin, self-operated Skill and POP Skill permissions are independent. Never replace a service failure with `authorized=true`, a locally invented result, a downloaded old private core or an offline fallback.

Python 3.12+, Node.js 22.15+, a logged-in HiOffice desktop client, JD network access and the existing business login are required. No Native Messaging host is installed. The helper sends the identity ticket only to the fixed HTTPS identity/authorization services, in memory. Model Keys and business cookies stay local. The core service receives only the business inputs required for the selected computation. Never include credentials in those inputs or log an identity ticket.

`provider-info` and existing local recovery/export commands remain available without making a core request. Generation and binding planning use the fixed protected service. A service version mismatch or identity, permission, transport or response-integrity failure stops new core work. It is not an ordinary failed image/SPU, and must not be counted as a successful skip. Let in-flight operations settle, preserve images, all sibling SKUs and original receipts, and reconcile unknown writes before any later resume. Do not start an old executor. Existing image concurrency, image cooldown rules and user authorization scope remain unchanged.

Install with the included `tools/install.py` from the distribution root. The installer verifies distribution hashes and installs the self-operated transport companion when applicable. It refuses to overwrite an old private/unprotected business Skill. Use a clean colleague profile; do not replace the owner's paused production installation. Upgrades preserve local-only files and stage conflicting incoming files under `.merge-candidates` for a three-way merge. Hashes detect corruption, not hostile edits by the machine owner; the server remains the enforcement boundary.

Share only the protected distribution, never a private source repository, server snapshot, production ledger, credential or cached business result. Deleting local authorization checks does not provide missing server computation. Already distributed full source, previously obtained results and a separately reimplemented workflow cannot be remotely revoked. Permission is for service use, not ownership of the colleague's computer or their independent JD access.
