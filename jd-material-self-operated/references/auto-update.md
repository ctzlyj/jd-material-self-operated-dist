# 启动时自动更新受保护自营客户端

## 使用者体验

安装包含更新器的完整受保护版本后，正常使用`self_operated_cli.py`或安全启动器即可。正式CLI在导入业务代码之前自动检查，每六小时最多一次，不常驻、不创建计划任务、不占浏览器标签页；不使用时不更新。`provider-info`和帮助不联网查新版，但仍遵守运行锁及未完成安装门禁。更新器不读取模型Key、Cookie或ERP票据，不调用模型或商品接口。

旧版没有更新器，必须先接入一次完整新版；不能声称仅发布GitHub就让旧电脑凭空拥有更新器。先查真实运行进程/锁，收妥后按原受保护安装器非破坏升级；已有本地修复由同事Codex自行合并并回归。维护人的私有安装与未安装的源码/下载目录不会自动更新。

## 可信来源与兼容条件

只从固定原公开仓库`ctzlyj/jd-material-self-operated-dist`读取非draft、非prerelease的`vYYYY.MM.DD.N`正式Release，解析tag到精确commit，要求该commit在`verify.yml`上的最新push工作流成功。下载固定HTTPS codeload的commit归档，不跟随main浮动代码或外部重定向，不需要同事GitHub登录。归档检查大小、根目录、路径穿越、重复大小写路径、链接与Windows非法路径；校验`DISTRIBUTION.json`和`PROTECTED_BUILD.json`完整文件SHA及产品/版本。

第一版自动应用限于明确兼容的客户端升级：`AUTO_UPDATE.json`协议1、固定产品/仓库、`compatibleFrom`含当前版本、`stateMigration:false`；核心版本、身份/鉴权/受保护设置、依赖清单以及共享浏览器组件不变，已有受管理文件不删除。旧版本号相同或更低不下载安装。模板和业务文件也接受清单校验，不允许清单写生产`.state`、凭据或缓存。

这不是所有未来版本都盲装：更换私有核心/依赖/共享浏览器组件或需要账本迁移的版本，交给当前Codex在本机评估兼容、已有活动任务和服务实际状态后处理。不能为了自动升级降低授权、改coreVersion碰运气、自动部署中央服务或覆盖其他Skill。只有真正需要服务方处理才升级问题；普通本地适配仍由同事Codex解决。

## 在途保护、事务与本地修复

- OS级独占锁覆盖一次正式CLI的更新和全部业务执行；实际执行的Python进程自身持锁，不靠历史PID或父进程存活推断。并发启动直接返回busy，不创建第二个worker、不替换运行中文件。指定原output存在执行锁也拒绝更新。不支持裸import业务函数绕过启动入口；自定义执行器应持同一`auto_update.session_lock`，旧绕行worker必须先收妥。
- 自动更新通过原安装基线判断本地修改。冲突或额外本地脚本保留原字节，将完整待合并程序暂存到同级`.self-operated-updates/merge-candidates/<version>/`，由Codex补合成回归、三方合并并验证；不能无条件覆盖、伪造官方SHA或清基线。生产状态与本地独有资料不纳入更新事务。
- 先备份将改变的程序文件和原安装基线，持久化事务，再逐文件原子替换并在新进程执行无模型/无业务写入的`provider-info`冒烟。验证通过才清事务；随后同一持锁进程重新载入完整最新CLI，避免旧入口字节码混用。
- 更新失败在业务启动前恢复原程序字节。断电/中断留下事务，下一次先恢复；发现新本地改动、损坏备份或不完整临时文件则保留证据停止，不盲目覆盖。此回滚只适用于尚未运行新版业务的安装事务，不允许用它回滚已运行过的新账本。
- 网络不可用保留旧可用版本，正常业务门禁继续生效；校验/兼容/合并问题保留候选和状态码，Codex自行排障。已回滚或待合并状态不会每次反复下载安装。更新原始异常不记录凭据；业务启动后的错误仍按原业务原因报告，不伪装成更新失败。

## 本机控制

由Codex在实际Skill目录执行，不需要用户学习命令：

```text
python scripts/auto_update.py status
python scripts/auto_update.py check
python scripts/auto_update.py disable
python scripts/auto_update.py enable
python scripts/auto_update.py recover
```

`status`只读本地状态；`check`显式忽略检查间隔，但仍遵守关闭设置/运行锁/兼容/校验；`recover`只核查安装事务，不处理商品未知写入。暂停任务不自动恢复，不清Key、不重试失败图片。出现候选冲突先读`autonomous-recovery.md`，不能建议重新下载覆盖本地修复。程序备份和下载候选保留在上述独立目录，不自动清用户文件。

## 维护人发布

客户端功能验证后再通过原公开仓库正式发布，main/tag CI与匿名下载验收继续保留。构建器默认生成空`compatibleFrom`，避免未经验证的新版本被自动采用；只有旧受保护安装到新版的升级/失败回滚/本地合并/核心兼容均验证后，才使用`--auto-update-from <已验收旧版本> ...`登记允许版本。声明兼容不替代测试，更不授权发布或服务部署。tag对应Release可见且commit CI成功后才会被使用者检查到；不把私有源码发布或本地候选称为同事自动升级成功。

回归：`tests/test_auto_update.py`覆盖正式版本/CI/固定来源、下载与清单、版本倒退、离线、暂停保留、本地修改、同进程全生命周期锁、独立进程竞争、失败回滚和中断恢复。受保护构建及干净安装也必须运行同一套测试。上线前还需获准同事设备验证，不宣称已逐机更新。
